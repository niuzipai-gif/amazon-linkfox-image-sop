# Amazon LinkFox 套图 SOP Skill 设计规格

日期：2026-08-26  
版本基线：公用 SOP V3.4  
目标 Skill：`amazon-linkfox-image-sop`

## 1. 目标与边界

把 Amazon 商品套图的公用 SOP 固化成一个可自动触发、可复制给同事、可公开发布的 Codex Skill。Skill 负责把资料确认、浏览器接管、LinkFox 配置、人类点击交接、九图 QA/修补、尺寸图生成和最终归档串成稳定状态机。

Skill 不保存任何个人账号、私人飞书链接、产品资料、电脑路径、团队权限或命名规则。使用者在自己的项目中提供项目根目录、最终图片目录、命名规则、权限指南和用户偏好。

Skill 不替代用户对产品事实的确认，也不代替人点击 LinkFox 的开始生成按钮。它只控制流程和安全边界，不凭旧聊天或旧网页推测本次产品资料。

## 2. 推荐架构

使用独立公开仓库，避免和现有运营技能仓库混在一起：

```text
amazon-linkfox-image-sop/
├─ SKILL.md
├─ agents/openai.yaml
├─ README.md
├─ references/
│  ├─ browser-preflight.md
│  ├─ linkfox-270-config.md
│  ├─ image-qa-and-repair.md
│  └─ public-configuration.md
├─ templates/
│  ├─ task-status.md
│  └─ user-preferences.md
├─ scripts/
│  └─ validate-sop-skill.ps1
└─ CHANGELOG.md
```

`SKILL.md` 只放触发条件、总流程、硬规则和引用路由；浏览器诊断、LinkFox 页面配置、图片 QA 和公开配置分别放入 references，避免每次加载整份长 SOP。

`README.md` 属于公开仓库的使用说明，包含安装方法、首次权限准备、最短触发口令、三个正常等待点和故障停止规则。它不包含私人环境地址。

## 3. 核心状态机

```text
资料待确认
  → 环境自检
  → LinkFox 配置中
  → 等待人类点击
  → 九图自动 QA/修补
  → 十图待最终确认
  → 已归档
```

每次任务使用唯一任务键和独立暂存目录。确认继续后，颜色、模板、逐图构图、修补授权和尺寸图风格不再零散追问；只有产品事实、真实尺寸、禁用项、归档位置或命名规则缺失时才一次性提问。

## 4. 浏览器接管闸门

在任何上传、填写或点击 LinkFox 前，Skill 先验证：

1. 能列出当前浏览器标签页；
2. 能按标题、网址、标签组和最近打开时间找到目标 LinkFox 页；
3. 能接管该标签页；
4. 接管后能读取标题、网址和页面加载状态；
5. 接管后能读到上传入口、商品信息框、模型/分辨率区和开始生成按钮。

前四项失败时，不刷新 LinkFox、不重复新开同类页面、不切换第二种控制面碰运气。每个问题最多做三次有针对性的检查；仍失败就报告准确阻塞点，并引导使用者按自己的权限指南处理。一个 Agent 或一种控制方式接管期间，其他 Agent 不得抢同一标签页；交还页面时必须标记 handoff。

## 5. LinkFox 生产规则

默认主图制作任务固定为：Img2、1K、中品质；普通图白底 1、卖点 2、场景 1、特写 1、特写白底 0；A+ 自定比例 W 9:H 6 共 4 张；LinkFox 共 9 张、270 算力。尺寸图不进入 LinkFox，由图像模型单独制作。

Skill 配置完成后必须停在“开始生成（270 算力）”前，等待使用者亲自点击、下载并回传九张图。Skill 绝不点击该按钮，也不因页面显示 240 就自行跳过主图；只有用户提供并明确验收主图时才允许记录 8 张/240 的例外。

商品信息必须是 S1、S3–S6、A1–A4 的逐图蓝图。尺寸、尺寸线、尺子和尺寸数字只进入尺寸图任务，不能写进 LinkFox 商品信息。

## 6. 图片修补与备用通道

收到完整九图或明确缺陷后，Skill 自动映射槽位并检查数量、轮廓、颜色、包装、白底/场景职责、A+ 实际像素比例和水印。只补失败槽位，不整批重做。

图像修补路由固定为：内置图像模型第 1 次；针对同一明确问题第 2 次；两次仍失败立即转 GPT 网页图像模型。若网页通道也失败，报告三次尝试和准确错误，停止，不再寻找代码、拼图或其他制图工具。

九张合格后，直接用图像模型制作尺寸图；十张完成后进入最终确认，只有用户说“确认十张”或“按此归档”才命名和归档。

## 7. 公开配置与隐私

公开 Skill 使用占位变量：`PROJECT_ROOT`、`FINAL_ARCHIVE_ROOT`、`NAMING_SPEC`、`HUMAN_SETUP_GUIDE`。提交前扫描私人域名、用户目录、账号、Token、下载路径和真实产品资料；所有示例使用虚构产品或空字段。

用户偏好只能调整视觉、文案、拍摄文档使用和回执方式，不能覆盖 270 算力、人类点击、尺寸图隔离、图像模型限制、重试上限或产品事实优先级。

## 8. 验证与发布

验证分四层：

- Skill 结构：运行 Codex `quick_validate.py`，检查 frontmatter、目录名和未完成占位符；
- 规则回归：脚本检查 270、4 张 A+ 9:6、尺寸图隔离、三次停止、人类点击交接等硬规则；
- 公开安全：扫描私人路径、飞书个人链接、账号和密钥；
- 使用烟测：在隔离临时目录中用一份虚构任务资料验证状态输出，不打开网页、不上传、不消耗算力。

发布阶段再用 GitHub 工具创建或绑定公开仓库，提交 Skill、README、references、templates、验证脚本和变更记录；不把本机工作区文件、诊断日志或私有产品图提交进去。

## 9. 验收标准

Skill 只有同时满足以下条件才算完成：

- 新同事只给项目路径、归档路径、命名规则和产品资料就能触发完整流程；
- 没有浏览器接管证据时不会上传或填写 LinkFox；
- 默认任务不会错误使用 240 算力、3 张 A+ 或在 LinkFox 制作尺寸图；
- Agent 会停在开始生成前并等待人点击；
- 九图缺陷只修失败槽位并按规定切换图像通道；
- 公开仓库不含私有地址、账号、Token、本机路径和产品资料；
- 规则验证、隐私扫描和隔离烟测全部通过。
