# 浏览器接管前置检查

这份规则解决一个常见误判：Chrome 能列出标签页，不代表 Agent 已经能控制页面。只有“找到目标页、接管成功、接管后能读页面”全部通过，才允许进入 LinkFox。

## 什么时候检查

- 新设备、新账号、新 Chrome/Edge 个人资料、新 Agent、扩展重新安装或上次任务出现超时后，必须重新检查。
- 同一设备如果有一份仍有效的环境记录，且设备、账号和扩展状态没有变化，可以跳过重复权限说明，但仍要做一次短的接管读取。
- 没有产品资料或没有收到“确认继续”时，只能做本检查，不能上传、填写、生成或消耗算力。

## 四步最小测试

按当前浏览器控制技能选择唯一控制面，不要同时使用两个浏览器工具。

1. 通过当前浏览器控制面的 `openTabs()` 列出用户当前打开的标签页；
2. 用可见标题、网址、标签组和最近打开时间找到本任务页面；
3. 把精确匹配对象传给 `claimTab(tab)` 接管；
4. 接管后读取标题、网址和页面加载状态。

接管后才检查 LinkFox 的页面状态：上传入口、商品信息框、模型/分辨率区和“开始生成”按钮都能读到，才算“LinkFox 已接通”。不要以“浏览器窗口开着”“标签页能看到”或“页面看起来像 LinkFox”代替这四项证据。

## 失败怎么处理

- 每次列出、接管或读取失败，先记录错误指纹、页面状态快照、当前控制面、对症动作和下一状态判据；不要固定等待 20–30 秒。
- 若是标签页交还后找不到，用当前浏览器的 `openTabs()` 用户标签列表重新匹配，再把精确对象传给 `claimTab(tab)`；这只有在标签列表或页面状态发生变化时才继续，不得重复同一动作。
- 不设固定尝试次数上限。一次恢复必须带来可验证的状态变化，或切换到一个先完成交还、记录原因且能力明确不同的控制面；同一错误指纹、同一状态和同一动作禁止重复。
- 默认每个浏览器故障事件使用 10 分钟恢复时间预算；有持续状态进展时可延长短窗口。达到目标状态、对症动作耗尽、时间预算用尽或出现权限/安全风险时，立即报告“浏览器控制阻塞”和准确原因，并指向使用者自己的权限指南。
- “能列出标签页、但接管或读取超时”属于浏览器会话/控制通道问题，不属于 LinkFox 商品信息问题。不要靠刷新 LinkFox、新建同类页面或反复关闭弹窗解决。
- 如果出现“另一个任务正在控制”“active writer”或用户正在操作的提示，先交还当前标签页并关闭同一页面的其他控制任务；不能抢占同一标签页。
- Chrome 或 Edge 被明确指定时，不要擅自切换到另一浏览器。应让使用者在指定浏览器开启 ChatGPT 浏览器扩展，并按自己的首次权限指南处理。

## 任务互斥与交还

一个任务只保留一个浏览器控制会话和一个目标标签页。任务等待人点击、用户查看页面或本轮结束时，把标签页标记为 `handoff`；下一次需要继续时，使用当前用户标签列表按标题、网址、标签组和时间重新匹配后接管。若必须切换控制面，先交还旧会话并记录切换理由，再建立新会话和新的状态判据；不并行控制同一页面。浏览器会话清理只处理本任务创建或明确交付的标签页，不关闭用户的其他页面。

## 通过后的记录

任务状态中至少记录：检查时间、浏览器家族、目标页标题/网址、接管读取结果、LinkFox 四个页面状态，以及“未上传、未填写、未点击生成”。若任一项为失败，状态保持在“资料待确认”或“浏览器控制阻塞”，不得进入 LinkFox 配置中。
